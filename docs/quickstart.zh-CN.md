# Codex HUD 本地候选版快速指南

## 下载、校验和打开

- 仅 Apple Silicon（arm64），目标 macOS 13+，不支持 Intel。当前开发机为 macOS 26.2；13/14/15 与无 Xcode/CLT 的干净机器未实机验证。
- 免编译表示终端用户无需 Swift/Xcode，不表示零配置或免 Gatekeeper 检查。
- 本轮仅生成本地候选包，版本仍是 1.1.0，未上传或替换任何 GitHub Release。以后发布时下载 `CodexHUD-macOS-arm64.zip` 及同名 `.sha256`。
- 可选校验（在这两个文件所在目录运行）：

```sh
shasum -a 256 -c CodexHUD-macOS-arm64.zip.sha256
```

解压得到 `Codex HUD.app`、本指南和项目 `LICENSE`。请先把 app 移到“应用程序”作为固定位置，再打开。移动或删除 app 会使后面的接入路径失效。

应用使用 **ad-hoc 签名，未做开发者公证**。确认来源和校验值后，若系统阻止首次打开：先尝试打开一次，再到 **系统设置 → 隐私与安全性 → 仍要打开**，按系统提示确认。详见 [Apple 官方说明](https://support.apple.com/zh-cn/102445)。受管理的 Mac 可能不允许放行；损坏/已知恶意软件警告不是这套操作的适用情况。不要关闭系统安全保护。

干净机器、GitHub 下载后真实 quarantine、真实 Gatekeeper 弹窗以及 Claude 直接调用 app 内二进制是否被拦截，均未验证。

## Codex 原有功能

Codex Weekly、Token、任务和重置卡保持原有口径，见 [项目中文说明](https://github.com/chenlongzhen/codex-hud/blob/main/README.zh-CN.md)。此功能不新增 Codex 账号访问方式。Claude 没有“重置卡”；Claude 的 Reset 只表示额度窗口重置时间，不进入 Codex 卡片数量或提醒。

## 可选：让本机 AI 帮你配置状态栏桥接

不想理解配置或命令时，把 [AI 接入文档](https://github.com/chenlongzhen/codex-hud/blob/main/docs/claude-setup-for-agents.zh-CN.md) 交给能操作本机文件的 AI，并说：

> 请按这份文档帮我接入 Claude 额度。先检查应用和配置位置，备份并保留我的已有设置及状态栏，不读取登录凭据。完成配置和合成验证后，告诉我如何确认真实数据。

该文档是源码文档新增内容；此前生成的候选 ZIP 尚未包含它，可单独下载交给 AI。AI 不应直接执行你的原状态栏命令试探，也不能把完成配置说成真实额度验证成功。

## Claude：默认自动查询

1. 本机需已安装并登录官方 Claude Code。HUD 默认同时开启 Claude 展示和主动查询，启动10秒后首次查询，通常每15分钟一次；无须保持 Claude Code 窗口打开。
2. 设置 → Claude 额度可关闭主动查询，选择15/30/60分钟，或填写可信的 Claude 可执行文件绝对路径。路径留空自动检查常见安装位置；“检测路径”找不到时会执行登录 shell，可能运行你的 shell 启动文件。
3. “立即查询”至少间隔60秒；展开或顶部刷新只是重读快照。睡眠暂停；唤醒至少等30秒；失败退避至最多4小时。需要登录、路径不可信或不支持账户时停止自动重试，处理后点“立即查询”。
4. HUD 在自己的空私有目录启动 CLI，固定参数为 `--safe-mode --strict-mcp-config /usage`；首次只对完整匹配该目录、默认选择“No, exit”的信任提示自动确认。其他提示不自动操作。错误或变化的界面布局会拒绝解析。

HUD 不直接打开登录凭据/钥匙串，也不自己调用账户接口；**官方 CLI 仍使用已有登录并联网**，可生成信任/会话记录。HUD 不删除这些记录。`/usage` 不发送模型任务，但不能把某一版本的0 token实测当作未来版本保证。自动更新被禁用。终端原始输出仅在内存中保留，输出只公开解析后的额度与状态。

快照写为 schema 2，兼容读取 schema 1；旧版 HUD 不支持 schema 2，降级前停止来源并清除观测。未提供Fable单独周额度或Claude重置卡。

## 可选：一次手动接入状态栏桥接

无需桥接也能主动查询；桥接可提供正在使用 Claude Code 时的被动观测。桥接本身不联网、不启动子进程。先自行打开 Claude 用户设置文件（通常是 `~/.claude/settings.json`），判断是否已有 `statusLine`；**先备份该字段及全部相关配置**。

### A. 我还没有状态栏

1. 在 HUD 设置 → Claude 额度 →“我还没有状态栏”，复制最小接入片段。
2. 手动把其中的 `statusLine` 字段合并进 Claude 设置，**保留其他所有内容**。不要把整个设置文件替换成片段。
3. 片段用 app 的实际可执行路径。路径包含系统随机化的 `/AppTranslocation/` 时复制按钮禁用：先移动 app 后重新打开。临时测试路径不能当成永久接入路径。
4. Claude 状态栏会显示类似 `5h 58% · W 77%`（剩余百分比）。缺失窗口不显示；没有有效窗口只输出空行。

### B. 我已有状态栏：纯文本生成器

不使用 A 替换现有状态栏，否则会丢掉原 command。HUD **仅生成文本，不执行/测试粘贴命令，不写脚本、不读真实设置、不记录粘贴内容**。

1. 在设置中选“我已有状态栏”。从你自己的设置中复制 **command 的完整 JSON 字符串值，包括外层双引号**，粘贴到输入框。不要手工替换 `\"`、`\\` 等转义；生成器使用标准 JSON 解码。
2. 明确选择原命令使用的 `/bin/sh`、`/bin/bash` 或 `/bin/zsh`。原命令会在该 shell 的独立 `-c` 上下文运行，不是粘进函数；保留 cwd、环境和 stderr，stdout 与退出码仍来自原命令。原命令原先的权限/隐私风险不被 HUD 消除。
3. 审阅并复制生成的组合脚本，手动用纯文本编辑器保存为 `~/.claude/codex-hud-statusline.sh`（自定义位置需自己同步修改 command）。也可在**确认剪贴板确实为脚本文本后**手动运行：

```sh
pbpaste > "$HOME/.claude/codex-hud-statusline.sh"
```

4. 复制“command JSON 字符串”，仅替换现有 `statusLine.command` 的值。默认值对应 `/bin/sh "$HOME/.claude/codex-hud-statusline.sh"`。**保留 `type`、`padding`、`refreshInterval`、`hideVimModeIndicator` 和其他原有字段**，不要删除整个 `statusLine`。现有状态栏自己的计时器保留。
5. 原 command 输入仅在当前设置窗口内存中，关闭后不保存；自行妥善保留备份。

组合脚本先收集 stdin 到 EOF，再给桥接和原命令。收集阶段**没有大小或时间上限，不在桥接 2 秒预算内**；shell 变量不能保存 NUL（规范 JSON 没有裸 NUL）。512 KiB 输入和末尾换行已用合成数据测试，不是对任意载荷/内存的保证。桥接超过 256 KiB 会拒绝采集，但原命令仍收到输入。

桥接预算从 main 起，在正常调度下最多 2 秒；不包含进 main 前加载、输入收集和原命令运行时间。不能保证总延迟、任意 fd 的单次写入原子性或所有孤儿进程行为。外部 SIGKILL、崩溃、系统冻结不属于“可处理错误返回 0”的承诺。桥接失败不影响原命令输出。对进程组发 SIGTERM 的合成取消已测试，但只给 wrapper 发信号可能不终止后代，**真实 Claude 的 shell/进程组取消语义未验证**。

## 如何确认与排障

- 在信任的 Claude Code 工作区发一条消息。额度字段通常要等第一次 API 响应后才出现；只对支持的订阅（Pro/Max/Ultra）或部分 gateway 提供。某个窗口缺失不代表对应套餐没有限额。
- 组织策略 `disableAllHooks` / `allowManagedHooksOnly`、项目级/本地级设置可能阻止或覆盖状态栏。
- 先在 Finder 打开并允许 app，再尝试接入。Claude 直接执行未公证二进制的拦截情况未验证。
- app 移动/删除后重新生成配置；不要保留临时验收 app 的路径。
- 从桥接成功写快照起，HUD 每 5 秒重读一次；手动刷新或展开会请求重读。它们不会向 Claude 发请求。官方只承诺 `refreshInterval` 重跑命令，未承诺重新查询账户额度。
- 可由你本人将显示值和 `/usage` 在各自观察时刻比对；时刻和舍入不同，不能保证完全一致。

## 状态含义

| 显示 | 含义 |
|---|---|
| 尚未收到桥接数据 | 尚无快照，可能尚未运行来源，不断言未配置 |
| 等待数据 / 未提供 | 桥接运行过，但没有对应额度字段 |
| 本地观测 | 有有效窗口；不是已证实的服务端当前值 |
| 旧 / N 分钟未确认 | 15分钟既无主动确认，也无数值/Reset变化；桥接重复接收不刷新此时钟 |
| 主动查询 · N 分钟前 | 官方 CLI 最近一次成功解析的额度；TUI 百分比/重置时间可能取整 |
| 已到重置点 · 待同步 | 保留已过期观测作为证据，不推测为 100% 剩余 |
| 读取失败 · 类别 | 快照损坏、权限或时间异常等；数字清空，不伪装从未接入 |
| 5h 观测为已用尽 | 仅 used=100；少于 1% 剩余显示 `<1%`，不舍入成耗尽 |

同屏显示两平台；CL 和菜单的 C W 数字始终是 Claude Weekly，5h 耗尽独立提示。双标签 46×166pt，关闭 Claude 后回到原 36×108pt 单 Codex 标签；关闭会停止显示/读取/主动查询，**外部桥接仍可继续采集**。

## 来源、账号与新鲜度限制

这是**定期查询/本地观测，不是账户实时同步**。主动查询时间是 CLI 返回的本机时刻；桥接时间只表示本机收到 JSON，重复输入不证明服务端刚更新，也不会推迟主动查询周期。其他设备用量等下次查询才可能反映。旧会话重播可能覆盖新值；没有源序号，不能证明账户顺序。Fable 单独周限额不在此数据里。

只支持一个配置来源；多个 `CLAUDE_CONFIG_DIR` 共用一份快照，不能证明或区分账号，会混写。切换账号先停止旧来源，再清除观测。系统时钟回拨时保留旧文件并等待恢复，可能提示时间异常。没有新有效观测前，不将旧观测包装成“刚更新”。

## 断开、恢复与卸载

- 先在 HUD 设置关闭“定时向 Claude Code 查询额度”，再处理可选桥接；仅清除快照不停止正在运行的来源。
- 已有状态栏：**先恢复备份的原 command 和全部相关配置，再删除组合脚本**。不要默认删除整个 `statusLine`。
- 原来没有状态栏：移除自己添加的桥接 `statusLine`；如后来增加了其他状态栏配置，先备份和人工合并，不盲删。
- 然后可在 HUD 设置中“清除 Claude 观测”。清除只删快照，稳定锁保留；运行中的来源会重建快照，换账号前必须先停旧来源。HUD 不替你修改 Claude 设置。
- 卸载：先断开 Claude 桥接并退出 HUD，再删 app。可选删除 `~/Library/Application Support/Codex HUD/`（这也会删除 HUD 偏好）；登录项若已由你开启，请先在设置里关闭。
